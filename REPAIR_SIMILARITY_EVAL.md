# Eval аналогов со схожим ремонтом

`eval_repair_similarity.py` — отдельный офлайн-challenger. Он не меняет
production, не пишет в реестр отправок и не вызывает OpenAI. Источник данных —
локальный Cleaner baseline с уже готовыми `interior_score`.

## Запуск

Быстрая проверка:

```powershell
$env:PYTHONUTF8='1'
python eval_repair_similarity.py --max-targets 500 --bootstrap 100
```

Основной временной eval и инспекция известной сделки:

```powershell
$env:PYTHONUTF8='1'
python eval_repair_similarity.py `
  --max-targets 2500 `
  --bootstrap 1000 `
  --inspect-id 1015853709 `
  --known-deal 1015853709=550000
```

`--max-targets 0` означает все доступные цели. При временном режиме число целей
может всё равно оказаться меньше лимита.

## Проверяемая логика

- Сравниваются квартиры той же комнатности, площади и класса здания, уже
  отобранные Stage 3.
- Для не-ЖК полный вес получают дома с разницей этажности не больше двух.
- Разные ЖК одного класса допустимы с коэффициентом уверенности 0.60.
- `5.8` и `6.2` принадлежат разным переходным зонам и не смешиваются.
- `6.3` и `6.9` принадлежат устойчивому хорошему диапазону и сравниваются.
- Вес каждой строки зависит от географического уровня, сходства ремонта,
  покрытия фото и отношения зданий.
- Вероятные физические дубли делят между собой один вес.
- При пяти и более аналогах крайние цены winsorize-ятся по взвешенным p10/p90.

Adaptive-policy:

- если в доме есть минимум два аналога со схожим ремонтом — внешний сигнал не
  вмешивается;
- если внешних аналогов нет — внешний сигнал равен нулю;
- 1–2 внешних аналога: cap 25%;
- 3+ внешних аналога: cap 75%;
- фактическая доля дополнительно умножается на confidence, зависящий от
  effective sample size и качества фотооценок.

## Результаты

Файлы создаются в `cache/repair_similarity_eval/`:

- `summary.csv` — общие метрики и парный bootstrap CI улучшения;
- `temporal_split_metrics.csv` — ранняя calibration и поздняя validation
  половины hold-out;
- `bucket_metrics.csv` — разрезы по ЖК, ремонту, размеру когорты, наличию
  похожих аналогов и benchmark confidence;
- `predictions.csv` — построчные прогнозы всех вариантов;
- `inspection.json` — веса каждого аналога для `--inspect-id`;
- `config.json` — точная конфигурация воспроизводимого запуска.

Положительное `mean_improvement_vs_current` означает снижение ошибки.
Улучшение считается устойчивым, если `mean_improvement_ci_low` также больше
нуля.

## Ограничения

Массовый eval использует asking price как proxy. Это не цена договора и не
доказательство сдачи. `--known-deal` влияет только на инспекцию указанной
квартиры и не подмешивается в агрегированные временные метрики, если объект не
принадлежит hold-out. Сначала следует накопить lifecycle и реальные сделки, а
затем повторить сравнение на них перед переносом challenger в production.
